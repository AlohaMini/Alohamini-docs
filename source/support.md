# 整机排错

适用：**AlohaMini 2 / 2 Pro**。将语雀 E001–E004、常见问题与当前软件配置整合为可逐项核对的步骤。完整报错见 [语雀异常处理正文](yuque/troubleshooting.md)。

## 先确定故障发生在哪一端

| 现象 | 先检查的位置 | 继续阅读 |
|---|---|---|
| 树莓派不亮、运行中重启 | 机器人供电、电源板与电池 | [开箱供电图](unboxing.md) |
| PC 找不到主臂 | PC USB、驱动板电源、串口别名 | [设备配置](configuration.md) |
| Host 缺少 8–11 号舵机 | 机器人左侧总线、左右从臂端口 | 本页 E002 |
| 校准提示上下限相同 | 当前设备对应的校准文件 | 本页 E001 |
| 启动相机后超时或退出 | Pi 供电、USB、相机路径和启用配置 | 本页 E003 |
| 从臂动作方向或幅度不对 | profile、校准、两端整机型号 | [校准](calibration.md)、[遥操作](teleoperation.md) |

## E001：校准最小值与最大值相同

**原文原因**：触发重新校准后，没有实际移动关节，就确认保存了范围。

1. 停止遥操作，确认当前终端连接的确实是目标机械臂。
2. 核对主臂 `am-leader-6dof`；标准 2 从臂 `am-follower-6dof`；Pro 从臂 `am-follower-6dof-hd`。
3. 按 [校准步骤](calibration.md) 重新记录零位和活动范围。在程序要求手动采集范围时，缓慢移动每个关节到允许的行程范围，避免强行顶住机械限位。
4. 确认所有关节都记录到变化，再按程序提示保存。
5. 使用与校准相同的设备路径和 ID，先验证单臂小幅动作，再启用整机。

校准数据不能从另一只机械臂直接复制。范围异常时重新完成测量，不要手工填数值来绕过检查。

## E002：左侧总线缺少 8–11 号舵机

二代 AM-ARM 的关节为 **1–7**；底盘车轮为 **8、9、10**；升降为 **11**。左侧总线需要同时连通机械臂和底盘／升降支路，右侧仅连接机械臂。语雀中的 1–6 号机械臂描述适用于 SO-ARM。

1. 停止 Host 并断开执行器电源，检查左臂驱动板两条总线是否接牢。
2. 检查底盘到升降再到左侧驱动板的连接，避免漏接支路。
3. 重新供电后，在树莓派上读取左总线状态：

```bash
python examples/debug/motors.py get_motors_states \
  --port /dev/am_arm_follower_left
```

4. 若只读到 1–7，核对是否将左右 USB 端口认反，再检查底盘／升降支路。
5. 对照 [设备配置](configuration.md) 重新绑定左右别名；确认所需舵机均能读取后再启动匹配机型的 Host。

## E003：树莓派启动多个相机时超时

语雀记录了电压或电流不足导致无法同时启动多个摄像头的情况。但 `Timed out waiting for frame` 也可能来自错误端口、被其他进程占用、USB 带宽或不受支持的分辨率。

1. 对照 [供电图](unboxing.md) 检查电池电量、电源板接口和线缆。
2. 先停止 Host，确认摄像头没有被其他预览程序占用。
3. 用 [相机发现步骤](configuration.md) 单独检查每一路设备及支持的格式。
4. 先启用一台相机，稳定后逐路增加；记录哪一路或哪种组合触发错误。
5. 树莓派与 PC 使用一致的相机配置，修改后重启两端程序。

交付教程出现的 `head_top` 与 GitHub 示例中的 `forward` 是两套命名，必须核对实际数据键和设备别名。不能把一套名称的数据直接交给另一套配置训练或推理。

## E004：无法读取舵机状态或指示灯不亮

1. 确认驱动板有独立电源，并核对该臂对应的电压；USB 连接本身不等于舵机已供电。
2. 检查数据线、端口权限和串口别名，关闭占用同一串口的其他程序。
3. 断电后重新检查接头，逐段核对串联线路。
4. 需要隔离故障时，每次断电后只接一个已确认兼容的舵机，再进行读取测试。
5. 在电源、数据线、端口和已知正常舵机都验证后仍失败，再联系支持方判断是否需要更换驱动板。

原文提供了将夹爪单独接入驱动板的排查思路；一次通信失败并不能单独证明控制板损坏。

## 更新软件与网络访问

先保存本机配置，再更新。不要把 `git restore .` 当成常规更新步骤，它会丢弃未提交的工作区修改。

```bash
cd lerobot_alohamini
git status
git diff
```

如果有本机配置改动，先备份或提交并确认用途；工作区准备好后再执行：

```bash
git pull --ff-only
```

提示无法快进时，先处理本地提交与远端的差异，避免直接覆盖。更新完成后核对 Pi 与 PC 的软件版本、机型和相机配置。

若使用自己局域网内的代理，可以按原文在当前终端设置：

```bash
# 替换为你自己的代理服务器地址和端口
export http_proxy=http://192.168.50.XXX:7890
export https_proxy=http://192.168.50.XXX:7890
curl -I https://github.com
```

代理程序需要允许该局域网客户端连接。以上占位 IP 不能直接运行，也不应沿用截图中的他人地址。

## 提交问题时提供这些信息

- 型号：2 / 2 Pro，主臂与从臂 profile。
- 出错位置：Pi Host、PC 遥操作、采集、训练或评估。
- 完整命令，替换私人目录等不需要公开的信息。
- 报错末尾、左右设备别名、启用的相机名称、最近改动。
- 故障能否在单臂或单相机下重现。
